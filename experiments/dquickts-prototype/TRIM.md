# dquickts trim recipe

Produces the minimal tree `packages/durablets/vendor/dquickts` (the
DurableTS Makefile default, installed there by
`packages/durablets/re-vendor.sh`) from a pristine dquickts checkout
at the pinned commit (see `packages/durablets/UPKEEP.md` for the
pin). The minimal tree is what the DurableTS Makefile builds by
default.

## Method: keep-list, not delete-list

The minimal tree is built by copying ONLY the files on the keep-list
below out of the pristine checkout. Anything not on the list is
dropped. That means new upstream fat (a new language binding, new
examples, new tests) is excluded by default — the tree cannot silently
grow. Conversely, if a keep-list file vanishes upstream (renamed or
deleted), the copy fails loudly and the list must be updated here
before the re-vendor proceeds. Do not silently skip a missing file.

`re-vendor.sh` parses this list from the markers below, so this file
is the single source of truth for what the minimal tree contains.

## Keep-list

<!-- keep-list-start -->
.github/workflows/ci.yml
.gitignore
LICENSE
Makefile
README.md
VERSION
compat/test-closefrom.c
cutils.c
cutils.h
dtoa.c
dtoa.h
libregexp-opcode.h
libregexp.c
libregexp.h
libunicode-table.h

libunicode.h
list.h
python/opcode.h
qjs.c
qjsc.c

<!-- keep-list-end -->

Notes:

- `.github/workflows/ci.yml`, `.gitignore` and
  `compat/test-closefrom.c` are harmless strays kept for fidelity with
  the tree as originally trimmed; they are not compiled.
- `repl.c` is NOT on the list: it is generated by the build from
  `repl.js` via `qjsc` (see the dquickts Makefile, `repl.c` rule). It
  is gitignored upstream.
- Build outputs (`.obj/`, `libquickjs.a`, `qjs`, `qjsc`, `repl.c`)
  are produced by the build step, not copied.

## Build (after copying the keep-list and applying the patch)

```sh
make CONFIG_PYTHON= CONFIG_PYTHON_CAPI= CONFIG_TEMPORAL_INTL= qjs libquickjs.a
```

The build needs real disk — the default `make` fails on the 512MB
`/tmp`. `re-vendor.sh` builds under `~/workspace/`, never `/tmp`.

## Provenance

`re-vendor.sh` writes a `VENDORED_FROM` stamp into the minimal tree
(upstream commit, patch, date, recipe). The stamp is generated, not
part of upstream, and is not on the keep-list.
